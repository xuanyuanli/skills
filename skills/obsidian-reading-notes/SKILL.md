# Obsidian 读书笔记规范

处理 Obsidian 库里的读书笔记时，**格式即结构**：Obsidian 正文无法用 Markdown 控制字号，「字体大小」只能靠标题层级表达。因此层级错了，笔记的可读性和目录结构就一起错了。

## 何时用 / 不用

**用**：新建读书笔记、合并多篇笔记、把书摘/HTML/转换结果整理成笔记、检查已有笔记格式、决定某段内容该用什么层级。

**不用**：写普通代码文档；非 Obsidian 的 Markdown 仓库（那里的规范通常相反，会要求 H1）。

## 三条不变量

1. **文件名即标题**，正文不写与文件名重复的 `# 一级标题`
2. **不用 YAML frontmatter**（`---` 只作分隔符，不能出现在文件开头）
3. **合并只报告候选，不擅自合并**，除非用户明确批准

## 工作顺序

1. **确认范围**：单个文件、某个目录，还是整个库的某个子目录
2. **判断是否需要合并**：同目录内 `< 500 行` 的笔记是合并候选，先列出来给用户看
3. **定层级**：按下面的表把每个标题映射到正确层级
4. **修分隔符与加粗**
5. **清理残留**：`&nbsp;`、HTML 标签、反爬字符、页眉页码
6. **跑检查**：`python scripts/lint_notes.py <path>`

## 标题层级

| 层级 | 用途 | 示例 |
|---|---|---|
| （无 `#`） | 单篇笔记开篇即正文 | `Effective Java.md` 直接写段落 |
| `##` | 合并文件中的书 / 大主题 / 原独立笔记名 | `## 苦难辉煌`、`## 红木` |
| `###` | 章 / 节 / 课程模块 | `### 第四章 「围剿」` |
| `####` | 小节（少用，避免过深） | `#### 遵义会议前后` |

规则：
- 不要跳级（`##` 直接到 `####`），除非原书结构确实缺一层并已说明
- 标题只用 `#` 层级，**不要** `# **标题**` 双重标记
- 合并时保留各笔记原标题，降级为 `##` / `###`
- 层级深度到 `####` 为止；更细的内容用列表或段落

## 分隔符

| 场景 | 用法 |
|---|---|
| 同一 `###` 章内、多条并列摘录 | 单独一行 `---` |
| 不同 `##` 篇之间 | `---`，前后各留一空行 |
| 文件开头 | **禁止** `---`（会被解析成 frontmatter） |

## 加粗

- 首次出现的**人名、地名、机构、书名**可加粗：`**毛泽东**`
- **核心论断、定义性句子**整句或句内关键词加粗
- 不整段加粗；不在标题里加粗；一个段落最多一处加粗

## 列表与段落

- 并列要点用 `-` 无序列表；子级缩进 **2 空格**
- 同一段落内的多句摘录要分条时，用列表或章内 `---`，不要靠堆空行分隔
- 段落之间一个空行，不要两个以上

## 附件

- 默认路径：`assets/${noteFileName}/`，与 Obsidian 的 Custom Attachment Location 插件保持一致
- 笔记内用**相对路径**链接，如 `![](assets/书名/cover.png)`
- 禁止全局 `attachments/`、`images/` 目录（会让不同笔记的附件混在一起）
- 若库使用其他附件方案，以库的实际约定为准，并在交付说明里注明

## 合并笔记

判定：**同一目录内、Markdown 少于 500 行的笔记**是合并候选。

流程：
1. 列出候选（文件名 + 行数 + 主题），**只报告**
2. 等用户批准；未批准不得合并
3. 合并时保留各笔记标题，按主题归入 `##` / `###`
4. 同一章内多条摘录用 `---` 分隔；不同书/篇之间也用 `---`（前后空行）
5. 合并后检查：无重复标题、无孤立分隔符、层级连续

## BOOX / 书摘 HTML

- 每本书 → 独立 `.md`，或合并文件中的 `## 书名`
- 书内重复的章节名只保留一个 `###`
- 章内摘录用 `---` 分隔
- 原始 `.html` 可留在 `assets/` 作备份，正文以 Markdown 为准
- 清理 HTML 残留标签、`&nbsp;`、零宽字符、反爬插入的随机字符

## 与 PDF 转换衔接

若笔记来自 PDF/EPUB 转换（`pdf-to-markdown` 技能），转换后的正文仍须遵守本规范：先按本规范定层级，再删除 OCR 残留的页眉、页码和假标题。

## 检查脚本

```bash
# 检查单个文件或目录（递归）
python scripts/lint_notes.py path/to/note.md
python scripts/lint_notes.py path/to/读书笔记 --json

# 自动修复安全项：行尾空格、&nbsp;、与文件名重复的 H1
python scripts/lint_notes.py path/to/读书笔记 --fix

# 列出合并候选（< 500 行）
python scripts/lint_notes.py path/to/读书笔记 --candidates
```

检查项：

| 级别 | 检查 |
|---|---|
| error | 文件开头 frontmatter、与文件名重复的 H1、未闭合代码块、`# **标题**` |
| warning | 跳级标题、`&nbsp;`、行尾空格、制表符、全局附件目录、重复标题 |
| info | 合并候选（< 500 行） |

有 error 时退出码为 1，可直接用于 CI 或提交前检查。

## 交付前自检

- [ ] 文件名与正文标题不重复
- [ ] 没有 frontmatter，`---` 只作分隔符
- [ ] 层级从 `##` 起，最多到 `####`，无跳级
- [ ] 章内多条摘录用 `---` 分开，篇与篇之间有空行
- [ ] 加粗只用在人名/地名/书名/核心论断
- [ ] 附件在 `assets/${noteFileName}/` 下，用相对路径
- [ ] 没有 `&nbsp;`、HTML 残留、OCR 页眉
- [ ] 合并操作已获得用户批准，且未静默删除任何原文
