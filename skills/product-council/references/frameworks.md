# 四人框架详解与追问清单

SKILL.md 只给了骨架。这份文件补三样东西：每个框架的判定标准、常见误用、以及四人冲突时怎么处理。评审卡住时再读，不必一开始就加载。

---

## 一、俞军：用户价值与交易模型

### 1. 用户价值公式

```
用户价值 =（新体验 − 旧体验）− 替换成本
```

逐项拆：

| 项 | 包含什么 | 常见错误 |
|---|---|---|
| 旧体验 | 用户现在怎么解决（含「不解决」这件事） | 只和竞品比，不和「什么都不做」比 |
| 新体验 | 功能带来的增量，而非功能本身 | 把「我们做了 X」当成「用户得到了 X」 |
| 替换成本 | 学习成本、迁移成本、习惯改变、社交成本、心理成本、机会成本 | 只算点击次数，不算心智负担 |

判定问句：
- 旧体验是 0 时（全新场景），用户凭什么相信你？
- 替换成本 > 增量体验时，任何推广资源都是在填坑。
- 三个数都是估算时，写明量级（如「替换成本约等于一次重新配置，几分钟」），不要写成精确数。

### 2. 需求三属性

- **用户价值**：对用户是否真的有用
- **用户愿付价格**：愿意付出多少钱、时间或注意力
- **企业成本**：研发、运营、合规、履约成本

三者同时为正才是可持续需求。任意一项为负，都要说明由谁补贴、补贴多久。

### 3. 用户是需求的集合

不要问「用户想要什么」，要拆成三元组：

> 谁（可识别的人群）+ 什么场景（触发条件）+ 什么需求（要完成的任务）

然后用规模判断优先级：
- 这类人占目标用户的比例（给区间，别给整数）
- 需求发生频率（每天 / 每周 / 每年一次）
- 现有替代方案的满意度

### 4. 真实需求 vs 声称需求

| 信号 | 可信度 |
|---|---|
| 用户已经为此付费或付出额外劳动 | 高 |
| 用户在无提示情况下的重复行为 | 高 |
| 用户主动搜索、绕路、拼凑工具 | 中高 |
| 访谈中「我觉得挺好」「我会用」 | 低 |
| 问卷里勾选的优先项 | 低 |

结论要写：用哪个指标、观察多久、达到什么值算验证通过。

### 5. 定价与门槛的二阶效应

任何价格或门槛，同时作用在两侧：
- 用户侧：降低使用意愿 → 用户价值下降
- 企业侧：提高转化质量或收入 → 企业收益上升

必须写出净效应，而不是只写一侧。常见错误是用「筛选高质量用户」掩盖「把大部分用户挡在门外」。

## 二、张小龙：人性与克制

### 1. 人性驱动力

好奇、懒惰、虚荣、恐惧、贪婪、攀比、归属、掌控感。

判断产品在**顺应**还是**对抗**：顺应人性易起量、难留存；对抗人性易建立信任、难获客。写清这个交换。

### 2. 克制的三层检验

1. **删除检验**：删掉它，用户具体失去什么？说不出具体动作或信息 → 不做
2. **替代检验**：现有机制能否以更低成本满足同一需求？
3. **频率检验**：为低频需求付出高频的界面成本，是否值得？

克制 ≠ 少做功能。克制是**拒绝把内部诉求转嫁成用户负担**。

### 3. 工具观

- 好工具：用户带着明确目的来，完成即走，下次还来
- 坏工具：用红点、连续签到、情绪钩子制造停留

判定：如果用户知道你的推荐机制，还会感谢你吗？

### 4. 价值观红线（出现即反对，除非有强论证）

- 把用户本该看到的信息藏起来，换取点击或转化
- 默认勾选、诱导授权、难以取消
- 用焦虑、恐惧、攀比推动付费
- 数据造假、伪造社会证明（虚假销量、虚假评价）

### 5. 信息密度与审美

一屏内新增元素是否挤掉了原有重点？视觉噪音是否让用户需要「扫描」而不是「阅读」？

## 三、乔布斯：第一性原理与完整体验

### 1. 三个提问

1. 如果今天从零开始做这件事，它应该长什么样？
2. 用户在这个旅程里，需要做几次「翻译」（把自己的意图翻译成软件的规则）？
3. 我们是在解决用户的问题，还是在解决我们组织的问题？

### 2. 端到端旅程

按时间顺序写出：触发 → 进入 → 操作 → 等待 → 结果 → 异常 → 再次使用。

标出三类问题：
- **割裂**：同一概念在不同页面叫法不同、规则不同
- **反复横跳**：用户在两个入口之间来回
- **责任转移**：把本该系统处理的判断交给用户

### 3. 砍什么

不是砍功能数量，而是砍**并列选项**。每多一个选项，用户就多一次决策。
砍掉后如果核心任务仍能完成，这个选项就是噪音。

### 4. 复杂度归属

- 复杂度留给自己：默认值、智能推断、自动纠错、渐进披露
- 推给用户：配置项、模式开关、教程、免责声明

判定：这个复杂度，是因为技术难、组织拆不开，还是因为商业上想两头都要？后者最该被质疑。

## 四、马化腾：灰度与组织机制

### 1. 灰度七维度（挑最相关的 1–2 维，不要全用）

| 维度 | 判定问句 |
|---|---|
| 需求度 | 这个需求有多强？不做会怎样？ |
| 速度 | 多久能验证？能不能更快拿到反馈？ |
| 灵活度 | 上线后改起来贵不贵？参数能否配置？ |
| 冗余度 | 出问题有没有兜底、降级、回滚？ |
| 开放协作度 | 是否依赖其他团队/外部方？接口是否稳定？ |
| 创新度 | 是已验证模式的移植，还是全新假设？ |
| 进化度 | 这次投入能否沉淀为可复用能力？ |

### 2. 1% 与 99%

两类错误都要防：
- 为 1% 的极端需求骚扰 99% 的用户
- 为 1% 的商业化诉求恶化 99% 的体验

判定：这个改动的受益人群占比多少？受影响人群占比多少？受影响者能否选择退出？

### 3. 小步快跑

设计灰度时写清四件事：
1. **灰度单元**：按用户 ID、地区、品类、端、账号等级还是流量比例
2. **最小验证单元**：多少样本、多少天能有统计意义
3. **放量条件**：指标达到什么阈值加到 10% / 50% / 100%
4. **回退条件**：哪个指标跌破什么值立即回滚

「先灰度看看」不是方案，这四件事才是。

### 4. Don't make me think

用户是否需要读说明、看教程、试错才能用？如果需要，是产品没想清楚，不是用户不聪明。

### 5. 10/100/1000

- 10 个核心指标：定义、口径、当前基线
- 100 条用户反馈：从哪来（客服、社群、评论、访谈）
- 1000 个行为样本：埋点或日志，验证「说的」和「做的」是否一致

## 五、四人冲突时怎么处理

### 高频冲突对

| 冲突 | 本质 | 处理 |
|---|---|---|
| 俞军 vs 张小龙 | 规模与商业化 vs 克制与信任 | 分清这是「拉新阶段」还是「留存阶段」，阶段决定权重 |
| 乔布斯 vs 马化腾 | 终局体验 vs 渐进验证 | 不可逆部分按乔布斯做，可逆部分按马化腾灰度 |
| 张小龙 vs 马化腾 | 不做 vs 先小范围做 | 若改动可逆且能灰度，先做；若触及价值观红线，不做 |
| 俞军 vs 乔布斯 | 满足需求 vs 定义需求 | 存量市场听俞军，增量/新品类听乔布斯 |

### 三条纪律

1. **不要折中**：折中方案通常同时失去两边的优点。要么选一边并说明代价，要么设计一个同时满足两边约束的新方案。
2. **区分可逆与不可逆**：可逆决策快做，不可逆决策慢做。这是唯一合法的「看情况」。
3. **分歧要落到裁决动作**：查什么数、做什么实验、谁拍板、什么时候拍。

## 六、追问卡片（信息不足时直接问）

- 这个决策，最迟什么时候必须定？
- 如果什么都不做，会发生什么？
- 谁会因为这个改动受损？他们有多少人？
- 上线后第一个要看的数是什么？现在是多少？
- 最坏情况是什么？我们承受得起吗？
- 这件事做成了，用户会怎么描述它？
