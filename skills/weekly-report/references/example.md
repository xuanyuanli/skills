## 聚类

| 周报条目 | 对应提交 |
|---|---|
| 批量导出异步化 | `b71e8a2` `2d90f6c` `6c02b19` `8f21c04` |
| 优惠券叠加 | `c4a1e35` `9e77b02` `5b3c9d1` |

## 输出

```markdown
# 周报 · 10-18 ~ 10-23

本期 23 次提交，主线是批量导出、优惠券叠加与对账差异定位。

- **大功能｜批量导出异步化**：导出改为任务队列 + worker，前端轮询进度并支持失败重试。价值：万级数据不再卡住页面，运营可以关掉页面等结果。
- **大功能｜优惠券叠加规则**：叠加规则配置化，下单页展示每一项优惠明细，修复重复抵扣。价值：运营可自助调整活动，减少资损与客服解释成本。
- **小功能｜对账差异定位**：差异按订单聚合、支持导出，修复金额精度丢失。价值：财务从逐条核对变成按单定位。
- **小功能｜物流轨迹订阅**：接入承运商轨迹推送。价值：减少用户主动查件。
- **Bug｜导出文件异常**：修复文件名时区导致日期偏移、非 UTF-8 内容乱码。价值：导出结果可直接用于对账。
- **其他｜工程**：拆分导出公共包，供后台与开放平台复用。
```

## 为什么这样合并

- **同一能力的多天迭代合成一条**：`2d90f6c` 建表、`b71e8a2` 改异步、`6c02b19` 进度、`8f21c04` 重试，单看每条都只是「一部分」，合起来才是「批量导出异步化」。
- **修复跟随所属功能**：叠加券的重复抵扣（`5b3c9d1`）如果单独列进 Bug，会让人以为优惠券功能有问题；放进「优惠券叠加」更准确。相反，导出日期偏移和乱码是独立缺陷，单独归 Bug。
- **不把 `chore` 抬成大功能**：拆包（`a63d0b8`）对业务没有直接影响，放「其他」。

## 不合格的输出

```markdown
- feat: 批量导出改为异步任务
- feat: 新增导出任务表与 worker
- fix: 叠加券重复抵扣
...
```

问题：逐条翻译、按时间排、没有价值、读者无法判断这周到底做成了什么。
